## 2. Design and formulas

### 2.1 Dependence-aware bootstrap (`cluster_bootstrap_mean_ci`)
- **With clusters** (sessions, wallets, tokens), it resamples G whole clusters with replacement and takes the mean as
  Σ cluster sums / Σ cluster counts, vectorised. The design follows Cameron, Gelbach & Miller (2008).
- **With `clusters=None`**, it runs a moving-block bootstrap over the chronological order (Künsch 1989). The block length
  is ceil(n^(1/3)) (the Hall–Horowitz–Jing 1995 rate). Blocks are concatenated and truncated to n.
- **Outputs.** `ci_lo` = q_α and `ci_hi` = q_(1−α). These are one-sided bounds at level α each, which is the same as a
  two-sided 1−2α percentile interval.
- **Design effect.** `design_effect` = var_boot(mean) / (s²/n) with ddof=1 (Kish), and `n_eff = n / design_effect`.
  I chose the analytic s²/n as the iid variance rather than an iid bootstrap variance. That choice makes deff for iid data
  ≈ (n−1)/n ≈ 1.

### 2.2 `required_n(s, α, power, deff)`
- Formula: `ceil(((z_(1−α) + z_power)/s)² · max(deff, 1))`.
- Reference values [V, tested]: 451 at s=0.10 and 113 at s=0.20. Both match the table in VALIDATION_COMPLETION §6.
- At α=0.05 it gives 619, where the doc prints 618. The raw value is 618.3, so ceil gives 619 and the doc rounded.
- deff is floored at 1, so clustering can never lower the requirement.

### 2.3 `discovery_gate`
It follows the instruction and VALIDATION_COMPLETION §5.

| Verdict | Rule |
|---|---|
| PASS | the one-sided (1−α) lower bound of the bootstrap mean is > 0 |
| FAIL | the one-sided (1−α_fail=0.95) upper bound is < `min_useful_edge` |
| INCONCLUSIVE | otherwise |
| N/A | n < `min_n` (default 10, the frequency floor from the recommendation; n=0 is always N/A), or fewer than 2 clusters |

Other behaviour:
- `authorizes_capital=False` is always set.
- A bootstrap one-sided `p_one_sided` is returned so that Benjamini–Hochberg FDR (`benjamini_hochberg`, q=0.10) can be
  applied across the ledger family by the caller.
- **UNDERPOWERED rule.** The gate flags UNDERPOWERED when `n_eff < required_n_iid`. This is algebraically the same as
  `n < required_n(deff)`. The instruction text said "n_eff < required_n", but comparing n_eff against a deff-inflated N
  would count the design effect twice. Deviation surfaced (Q3).
- **Half-edge rule.** The recommendation also asks for "point estimate ≥ s_min/2". It is reported as `point_ge_half_edge`.
  It is enforced only with `require_half_edge=True`, and the default is False to follow the instruction's rule. Q2.

### 2.4 `deployment_gate`
There are three axes: ALPHA, EXECUTION and DEPLOYMENT. RISK is a separate block.

The convention-A thresholds are read from `cfg` (default `DEFAULT_GATE_CFG`) **unchanged**.

**ALPHA checks**

| Check | Rule vs legacy `run_gate` |
|---|---|
| provenance | `window_status ∈ {FRESH, PROSPECTIVE}`, else **FAIL `reused_window`**. An unknown status gives FAIL `unknown_window_status` |
| dsr | `deflated_sharpe_ratio(x, max(ledger_var, 1/N), nb_trials)` > 0.95. The legacy formula is reused; only the inputs change |
| nw_t | legacy `newey_west_tstat` > 2.0 |
| boot_lo | q_0.025 of the **cluster / moving-block** bootstrap Sharpe > 0. Legacy used iid resampling |
| wf_min | min Sharpe over **all** `wf_splits` folds > 0 (`subperiod_consistency_all_folds`) |
| mc | **substitute:** a recentred dependence-aware bootstrap p-value of the Sharpe, P*(SR(x*−x̄) ≥ SR̂), must be < 0.05. Legacy used sign-flip, which assumes a symmetric null (audit §6). See Q5 |
| pbo | `cscv_pbo(candidate_matrix, S=8)` < 0.05. Without a matrix, ALPHA is capped at **INCONCLUSIVE `pbo_unavailable`** |
| min_trades | n < 30 gives **INCONCLUSIVE** (audit §6 recommendation), not FAIL |
| max_params | ≤ 6 |

**Axis rules**
- **EXECUTION.** `cost_model_id` (a non-empty string), `capacity_estimate` (> 0) and `tail_loss_estimate` (≥ 0) are required.
  If any is missing, the verdict is INCONCLUSIVE with the missing field as the reason. The verdict is FAIL if capacity is below
  `deployed_size`, or if the tail loss exceeds `max_tail_loss` when that is given.
- **RISK.**
  - Reports the additive $ max drawdown and the same figure in **R** (÷ `risk_per_trade`) and as a **fraction of declared
    capital**.
  - Reports the worst max-DD over any 100-trade window (amount and R).
  - Reports the legacy compounding `max_drawdown(pnl/capital)` next to the **unchanged** 8% limit. Breaching that limit gives
    RISK FAIL `max_dd`.
  - A missing R or capital input gives INCONCLUSIVE.
- **DEPLOYMENT** is the combination of ALPHA, EXECUTION and RISK: any FAIL gives FAIL, otherwise any INCONCLUSIVE gives
  INCONCLUSIVE, otherwise PASS. `deployment_eligible` is True only on PASS.

### 2.5 Trials ledger (`tools/trials_ledger.py`)
- **Entry fields.** `id, family, dataset, dataset_group, data_window{start,end}, window_status∈{DEV,REUSED_HOLDOUT,FRESH,PROSPECTIVE},
  n_configs, sr_per_trade, n_trades, verdict, is_null_control, source, notes, registered_at, prev_hash, entry_hash`.
- **Append-only.**
  - `register_trial` refuses an existing id.
  - It re-verifies the SHA-256 hash chain before every append and refuses the append if the chain is broken.
  - `verify_ledger` detects in-place edits, deletions and reorders.
  - Writes are atomic (temp file + `os.replace`).
- **Overlap.** Freshness and overlap are judged per **`dataset_group`**. All CME equity-index futures (MNQ/MES/ES/NQ/M2K/MYM)
  are `CME_EQUITY_INDEX`, which matches how the checker counted 65 reads across MNQ+MES+ES. Date-only ends are inclusive.
- **`gate_inputs()`** *derives* the status. A window that any other trial has read becomes REUSED_HOLDOUT (or DEV, if the
  caller declared DEV), whatever the caller declares. PROSPECTIVE is honoured only on a fresh window.
- **`nb_trials`.** The default is `mode="configs"` (conservative: a larger SR0). `mode="families"` is also available.
  Null controls are excluded as candidates, but they do make a window non-fresh.
- **`empirical_sr_trials_var`** is the ddof=1 variance of per-trade SR over overlapping trials with N ≥ 30 and a known SR.
  The gate floors it at 1/N.
